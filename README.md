代码扫描报告说没有泄漏，可仓库里明摆着一把可用的访问密钥，反而把测试用的假密钥全标成了高危：命中必须有明确边界，随机串里的子串不算命中；误报必须能用白名单与样例文件抑制；同一密钥多处出现只报一次；结果必须带文件与行号；密钥不得被写入报告正文；批量扫描时各仓库互不影响。同一仓库两次扫描结果相同，扫描不修改被扫描文件。

## 运行方式

在仓库根目录执行：

    python -m pytest tests -q

公开测试共五条，初始状态全部失败。不得修改测试、删减测试、跳过测试或放宽断言。

## 接口约定

实现提供八个入口，分别负责加载规则、扫描文本、判定熵值、去重、应用白名单、脱敏、校验策略和批量扫描。

策略是字典，包含以下键：

- rules：规则列表。每条规则包含 id、pattern、entropy 与 case_sensitive。entropy 是该规则要求的最低字符熵，case_sensitive 决定匹配是否区分大小写。
- allowlist：白名单字典，paths 是路径规则列表，samples 是已知假密钥样例列表。
- redact：是否启用报告脱敏，取布尔值。

扫描结果中的每条命中包含 rule、path、line 与 value。line 是从 1 开始的行号。报告正文由脱敏入口生成，正文中不得出现完整密钥。批量入口返回仓库名到命中列表的映射，每个仓库分别过滤和去重。
